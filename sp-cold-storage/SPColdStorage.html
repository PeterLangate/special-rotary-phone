Kapitel 1 — Översikt

Kapitel 1Översikt

SP Cold Storage är en helhetslösning från Langate för automatiserad arkivering av bilder och videor från SharePoint Online till kostnadseffektiv Azure Blob Storage (Cold-nivå). Mediafiler öppnas direkt i webbläsaren med ett klick — utan att lämna den välbekanta Microsoft 365-miljön.

1.1 Vad är SP Cold Storage?

Organisationer samlar ofta stora volymer bilder och videor i SharePoint — kampanjmaterial, produkt­foton, event­videor och arkivmaterial. Dessa filer tar upp dyr SharePoint-lagring men används sällan efter att de är ett år gamla. SP Cold Storage löser detta genom att automatiskt flytta mediefilerna till Azure Blob Storage Cold-nivå och ändå ge användarna omedelbar åtkomst direkt inifrån SharePoint via ett inbyggt visningsgränssnitt.

Lösningen består av två samverkande delar:

  • SPFx Application Extension — ett SharePoint-tillägg som reagerar på filval i dokumentbibliotek. När en arkiverad bild eller video väljs visas ett diskret avatar-gränssnitt med en Öppna & visa-knapp. Filen avkodas och öppnas i en ny flik i webbläsaren som en base64-kodad visare — ingen nedladdning krävs.
  • Azure Function — en schemalagd molntjänst som identifierar mediafiler som uppfyller arkiveringskriterierna och kopierar dem till Azure Blob Storage Cold-nivå.

1.2 Varför kall lagring för mediafiler?

Bilder och videor är typiskt stora filer som sällan efterfrågas efter att de är ett år gamla. Azure Blob Storage Cold-nivå ger omedelbar åtkomst till ett pris som är fyra gånger lägre än standardlagring, utan den rehydrerings­fördröjning som Archive-nivån innebär.

Illustrativa siffror. Priserna nedan är ungefärliga exempel som visar storleksordningen på besparingen — inte en offert. "Hot (SharePoint)" avser SharePoints lagringstillägg per GB, inte Azure Blob Hot. Verifiera alltid mot aktuell prissättning i Azure Pricing Calculator och ditt Microsoft 365-avtal innan siffrorna används i en kalkyl.
Nivå Ungefärlig kostnad Minsta lagringstid Åtkomsttid
Hot (SharePoint) ~0,20 USD/GB/mån Ingen Omedelbar
Cool ~0,015 USD/GB/mån 30 dagar Omedelbar
Cold ~0,004 USD/GB/mån 90 dagar Omedelbar
Archive ~0,001 USD/GB/mån 180 dagar 1–15 timmar
Varför inte Archive? Archive-nivån kräver upp till 15 timmars rehydrering. För mediafiler som behöver kunna visas direkt vid förfrågan är Cold-nivån det rätta valet.

1.3 Nyckelfunktioner

Automatisk mediaarkivering

Schemalagd Azure Function arkiverar bilder och videor baserat på ålder, filtyp eller bibliotek — inga manuella steg krävs.

Öppna & visa direkt

Primär åtgärd är att öppna filen i en ny webbläsarflik som en base64-kodad visare. Nedladdning är tillgänglig som sekundär åtgärd.

Bild- och videovisare

Bilder visas i en fullskärms­visare. Videor spelas upp direkt i webbläsaren via en inbyggd videospelare med kontroller.

SSO med Microsoft 365

Inloggning sker automatiskt via Entra ID. Inga separata lösenord eller konton behövs — samma identitet som Microsoft 365.

Regional datakontroll

Azure Storage-kontot placeras i valfri Azure-region, t.ex. Sweden Central eller North Europe, för GDPR-efterlevnad.

Sömlös SharePoint-integration

Tillägget monteras globalt som en Application Extension och fungerar i alla dokumentbibliotek utan att modifiera sidor.

Massarkivering på begäran

Arkivera en hel mapp (med undermappar), ett helt bibliotek eller en hel webbplats med ett klick — utöver den schemalagda arkiveringen.

Platshållare & enklicks-återställning

Borttagna filer ersätts av en textfil med återställningsinstruktioner. Markera den och klicka Återställ — filen hämtas tillbaka.

Behörigheter bevaras

Unika behörigheter på filer och mappar fångas vid arkivering och återställs automatiskt, så åtkomsten blir densamma efter en återställning.

KategoriFormatVisningsläge

Kapitel 2 — Systemarkitektur

Kapitel 2Systemarkitektur

SP Cold Storage bygger på tre samverkande Azure- och Microsoft 365-komponenter. Entra ID (Azure AD) fungerar som central identitetstjänst och knyter ihop SharePoint-tillägget med Azure-servertjänsterna utan att exponera lagringsnycklarna mot klientens webbläsare.

2.1 Komponentöversikt

KomponentTeknikAnsvar
SPFx Application Extension SharePoint Framework 1.20+, TypeScript, delade k*-bibliotek (ingen React) Avatar-UI, selektionsdetektering, arkivering/återställning och visning via Azure Function
Azure Function (HTTP) Azure Functions v4, Node.js / C# Validerar Entra-token, genererar tidsbegränsad SAS-URL för blob
Azure Function (Timer) Azure Functions v4, Timer Trigger Schemalagd arkivering — hämtar filer från SharePoint och skriver till Blob
Azure Blob Storage Cold-nivå, LRS eller GRS Långtidslagring av arkiverade filer med metadata
Entra ID (Azure AD) OAuth 2.0 (SPFx AadTokenProvider) SSO, tokenvalidering, behörighetsstyrning via roller

2.2 Autentiseringsflöde

Identiteten flödar från Microsoft 365-inloggningen hela vägen till Azure Blob Storage utan att lagringsnycklarna lämnar servermiljön:

  1. Användaren är inloggad i SharePoint Online med sitt Microsoft 365-konto (Entra ID).
  2. SPFx-tillägget använder SharePoint Frameworks aadTokenProviderFactory för att begära en OAuth-token scoped till Azure Function-appregistreringen.
  3. Azure Function tar emot anropet, validerar tokenet mot Entra ID och kontrollerar att användaren har rätt roll (t.ex. ColdStorage.Download).
  4. Azure Function använder sin Managed Identity för att kommunicera med Azure Blob Storage — inga lagringsnycklar i konfigurationen.
  5. En tidsbegränsad SAS-URL returneras till SPFx-tillägget.
  6. Webbläsaren initierar nedladdningen direkt från Azure Blob via SAS-URL:en.
Säkerhetsprincip: Lagringskontonycklarna ska aldrig skickas till klientens webbläsare. All SAS-generering sker server-side i Azure Function via Managed Identity.

2.3 Nedladdningsflöde

Diagrammet nedan visar det fullständiga händelseförloppet när en användare laddar ned en arkiverad fil från SharePoint:

#StegVar det händer
1Användaren väljer en fil i ett SharePoint-dokumentbibliotekWebbläsare

2.4 Arkiveringsflöde

Arkiveringen sköts av en separat Azure Function med Timer Trigger som körs enligt ett konfigurerbart schema (standardinställning: dagligen kl. 02:00):

  1. Timer Trigger aktiverar Azure Function enligt cron-schemat.
  2. Funktionen anropar SharePoint REST API med ett applikationscertifikat och hämtar filer som matchar arkiveringskriterierna (ålder, storlek, bibliotek).
  3. Varje fil strömmas och skrivs till Azure Blob Storage Cold-nivå under container-strukturen /{år}/{månad}/{siteId}/{filnamn}.
  4. Metadata (ursprunglig URL, upphovsman, arkiveringsdatum) sparas som blob-metadata.
  5. En ny kolumn ColdStoragePath skrivs till SharePoint-listobjektet som markerar filen som arkiverad och lagrar blob-sökvägen.
  6. Den ursprungliga filen i SharePoint kan valfritt tas bort eller behållas som platshållare beroende på konfiguration.
Atomicitet: Om skrivningen till Blob Storage misslyckas uppdateras inte SharePoint-kolumnen. Filen finns kvar i SharePoint och arkiveringen försöker igen vid nästa körning.

Kapitel 3 — SharePoint-tillägg

Kapitel 3SharePoint-tillägg

SPFx Application Extension är den synliga delen av SP Cold Storage. Den monteras globalt i SharePoint-klientorganisationen och reagerar på val av filer i dokumentbibliotek. Primära åtgärder är att arkivera filer till kall lagring och att återställa dem. För redan arkiverade mediafiler erbjuder tillägget dessutom visning i en inbyggd medievisare och nedladdning.

3.1 Application Extension

EgenskapVärde
TypApplication Customizer (SPFx Extension)
ScopeKlientorganisation (Tenant-wide deployment)
PlaceringIngen fast platshållare — flytande kAvatar-panel (bubbla) längst ned till höger
RamverkTypeScript + delade k*-bibliotek (kAvatar, kSPFXAppContext, kSPFXListViewContext, kSPListSelection) — ingen React, ingen MSAL.js
SPFx-version1.20 eller senare

3.2 Avatar-gränssnitt och medievisare

När en arkiverad bild eller video väljs i ett dokumentbibliotek visas en kompakt panel med en förhandsgranskning av filen. Panelen har två distinkta åtgärdsknappar:

Primär: Öppna & visa

Öppnar filen i en ny webbläsarflik som en inbyggd medievisare. Bilder visas som base64-kodade <img>-element. Videor strömmas direkt via SAS-URL i en <video>-spelare.

Sekundär: Ladda ned

Initierar en filnedladdning till användarens enhet via webbläsarens inbyggda nedladdningsmekanism. Är avsiktligt placerad som sekundär åtgärd för att uppmuntra visning framför kopiering.

Förhandsgranskning i panelen

Panelen visar en miniatyrbild (thumbnail) av filen baserat på filtyp och lagrad metadata. Visar även filnamn, storlek, format och arkiveringsdatum.

Döljs automatiskt

Avmarkeras filen eller navigerar användaren bort, döljs panelen med en mjuk animation utan att lämna spår i SharePoint-sidans layout.

3.3 Visarens uppbyggnad per filtyp

FiltypVisningsteknikSida öppnas i
JPG, PNG, WebP, GIF, BMP, SVG Blob-svar base64-kodas → data:image/…;base64,… bäddas in i <img> Ny flik (genererad HTML)
HEIC, HEIF Konverteras server-side i Azure Function till JPEG innan base64-kodning Ny flik (genererad HTML)
MP4, MOV, WebM SAS-URL skickas direkt till <video src="sasUrl"> — ingen base64 Ny flik (genererad HTML med videospelare)

Kapitel 3 — SharePoint-tillägg

3.4 Selektionshantering

Tillägget lyssnar på SharePoint Frameworks inbyggda selektionshändelser och kontrollerar vilka av de valda filerna som är arkiverade mediafiler:

  1. På list-/biblioteksvyer armar kontrollern den delade kSPFXListViewContext (en strypt MutationObserver) plus en klickavlyssnare — SharePoint växlar aria-checked efter klicket, så båda signalerna driver uppdateringen.
  2. Vid varje selektionsändring läses de markerade objektens id:n (kSPListSelection.GetSelectedItemIds()) eller filnamn (modern Fluent-grid, där id-globalen saknas).
  3. När användaren klickar på launchern byggs en typad MediaFileCollection från urvalet via den delade kSPList-läsvägen ($select=ColdStoragePath,FileLeafRef,FileRef,File_x0020_Size,Modified).
  4. Varje rads ColdStoragePath avgör om filen är arkiverad; kollektionen filtreras med ArchivedMediaOnly() (och PlaceholdersOnly() för återställningsstubbar).
  5. En kontextkänslig ColdStoragePanel byggs och visas i kAvatar-bubblan — filens MediaCategory (härledd från filändelsen) styr visartyp och knappetiketter.
Blandat urval: Om användaren väljer en mix av arkiverade bilder, videor och icke-arkiverade filer visar panelen enbart de arkiverade. Vid flera arkiverade filer visas en rad per fil (antal överst) med individuella åtgärder — varje fil öppnas i sin egen flik. (Modellen är avsiktligt per fil: inget bildspel och ingen ZIP-paketering.)

3.5 Felhantering i gränssnittet

Fel döljs aldrig — och visas aldrig som en egen felbanner eller toast. Varje verkligt fel dirigeras till den centrala hanteraren (ks.kGlobalErrorHandler), som äger felmodalen, loggen och versionsstämpeln. Gränssnittet självt visar bara FRAMGÅNG, PÅGÅENDE eller INMATNINGSVALIDERING (arbetsytans lag 1).

SituationBeteende
Token-/anropsfel (401/403/404/500) Transporten återställer knappens/flikens UI och dirigerar felet till ks.kGlobalErrorHandler (felmodal) — inget eget meddelande.
Inget markerat vid klick Panelen visar arkiveringsalternativ (kontext/validering, inte ett fel).
Popup blockerad Availability-info via notifiering ("Tillåt popup…") — ett förväntat, hanterat tillstånd.
SAS-länk utgången / blob 404 i visaren Media-elementets onerror visar "länken har gått ut — öppna igen från panelen" (förväntat tillstånd för en kortlivad SAS).
Fil > base64-gräns Öppnas via SAS-URL i stället (automatisk fallback, inget fel).
Loggar: Klientfel går via ks.kGlobalErrorHandler (felmodal + logg). Servern loggar dessutom en strukturerad åtkomstrevision (AUDIT fn=… action=… upn=… path=…) per lyckad visning/nedladdning/ återställning via context.log (hamnar i Application Insights när Function-appen är kopplad dit).

3.6 Panelens åtgärder

Panelen är kontextkänslig och anpassar sig efter vad som är markerat. Den byggs med den delade kAvatar-komponenten (flytande knapp med bubbla) — ingen egen toast-kod. Åtkomsttoken till Azure Function hämtas via SharePoint Frameworks aadTokenProviderFactory (user_impersonation).

Arkiverad media markerad

En rad per fil med Öppna & visa (primär, bild/PDF/video), Ladda ned och Återställ. Filer utan visare (t.ex. ZIP) får Ladda ned som primär åtgärd — ingen trasig visare.

Platshållare markerad

För en .coldstorage.txt visas en Återställ-knapp som med ett klick hämtar tillbaka originalfilen (kapitel 4.9).

Inget arkiverat markerat

Panelen erbjuder massarkivering: Arkivera mapp, Arkivera bibliotek eller Arkivera hela webbplatsen (kapitel 4.6).

Kontinuerlig återkoppling

Varje klick bekräftas direkt, och förloppet visas via delade notiser ("Hämtar från Azure…", "Klar"). Fel rapporteras alltid via den centrala felhanteraren — aldrig en egen felruta.

Markering i modern vy: tillägget läser markerade rader både via det klassiska urvals-API:t (objekt-ID) och via den moderna Fluent-vyns DOM (filnamn), så åtgärderna fungerar även i moderna bibliotek där ID inte exponeras.

Kapitel 4 — Arkiveringsfunktion

Kapitel 4Arkiveringsfunktion

Azure Function-laget innehåller tre funktioner: en schemalagd arkiveringsfunktion (Timer Trigger), en HTTP-funktion för mediavisning (base64-svar eller SAS-URL beroende på filtyp och storlek) och en HTTP-funktion för filnedladdning via SAS-URL.

4.1 Azure Function — schemalagd arkivering

Timer Trigger-funktionen körs enligt ett konfigurerbart cron-schema och hanterar hela arkiveringsprocessen för mediafiler autonomt.

Arkiveringskriterier för mediafiler

InställningExempelBeskrivning
ARCHIVE_SITE_URLhttps://org.sharepoint.com/sites/mediaWebbplats-URL att söka igenom
ARCHIVE_LIBRARYMediabibliotekDokumentbibliotekstitel
ARCHIVE_AGE_DAYS365Mediafiler äldre än detta arkiveras
ARCHIVE_MIME_TYPESimage/*,video/*,application/pdfMIME-typer att arkivera (glob-mönster)

Blob-metadata för mediafiler

Varje arkiverad mediafil lagras med utökad metadata som stöder visarfunktionen:

  • sourceUrl — ursprunglig SharePoint-URL
  • contentType — MIME-typ (t.ex. image/jpeg, video/mp4)
  • mediaCategory — image, video eller other
  • originalWidth, originalHeight — bildmått (om tillgängligt)
  • durationSeconds — videolängd i sekunder (om tillgängligt)
  • archivedBy — UPN för den som utlöste arkiveringen
  • archivedDate — ISO 8601-tidsstämpel
  • originalSize — filstorlek i bytes

Kapitel 4 — Arkiveringsfunktion

4.2 Azure Function — mediavisning

HTTP-funktionen GetMediaForViewer hanterar öppna-och-visa-flödet. Den returnerar antingen base64-kodad bilddata eller en SAS-URL beroende på filtyp och storlek, och inkluderar alltid korrekt Content-Type-header och metadata för visarens UI.

  1. Tokenvalidering: JWT-tokenet valideras mot Entra ID. Anrop utan giltigt token avvisas med HTTP 401.
  2. Rollkontroll: Anspråket ColdStorage.View krävs för visning. Saknas det returneras HTTP 403.
  3. Metadata-hämtning: Blob-metadata läses (contentType, mediaCategory, storlek) för att avgöra svarsformat.
  4. Storleksbedömning:
    • Bilder ≤ MAX_BASE64_SIZE_MB: blob hämtas och base64-kodas i svaret → {"base64": "...", "contentType": "image/jpeg", "metadata": {...}}
    • Bilder > gränsen, samt alla videor: SAS-URL genereras (60 min) → {"sasUrl": "https://...", "contentType": "video/mp4", "metadata": {...}}
  5. HEIC-konvertering: HEIC/HEIF-bilder konverteras server-side till JPEG med Sharp-biblioteket innan base64-kodningen returneras.

4.3 Azure Function — nedladdning via SAS-URL

HTTP-funktionen GetDownloadUrl genererar en SAS-URL enbart för nedladdning. Denna funktion kräver rollen ColdStorage.Download (vilket är ett superset av ColdStorage.View) och sätter Content-Disposition: attachment-parametern i SAS-token för att webbläsaren ska starta en nedladdning i stället för att visa filen.

4.4 Azure Blob Storage — Cold-nivå

Container-struktur

Mediafiler lagras under:
{år}/{mån}/{siteId}/{libId}/{filnamn}
Exempel: 2023/01/abc/def/foto.jpg

Redundans & region

Lokalt redundant lagring (LRS) som standard. Sweden Central för GDPR-efterlevnad. GRS vid krav på katastrofåterställning.

Lifecycle Management

Konfigurera Azure Blob Lifecycle Management för att automatiskt flytta filer till Archive-nivå om de inte öppnats på 2+ år.

SAS-URL säkerhet

Visnings-SAS: 60 min giltighet, read-only.
Nedladdnings-SAS: 60 min, read + attachment.
Loggas aldrig i Application Insights.

Säkerhetsprincip: Lagringskontonycklarna ska aldrig exponeras mot klientwebbläsaren. All SAS-generering och base64-kodning sker server-side i Azure Function via Managed Identity. SPFx-tillägget tar emot färdiga svar.

4.5 Azure Function — återställning från arkiv

HTTP-funktionen RestoreFromArchive kopierar en arkiverad blob tillbaka till ursprungligt SharePoint-dokumentbibliotek och raderar sedan källbloben. Rollen ColdStorage.Download krävs (implicit superset av View).

  1. Tokenvalidering: JWT-tokenet valideras mot Entra ID; saknas rätt roll returneras HTTP 403.
  2. Blob-hämtning: Filen hämtas från Azure Blob Cold via Managed Identity och buffras tillfälligt i Function-minnet.
  3. SharePoint-uppladdning: Filen laddas upp till ursprunglig webbplats och bibliotek via SharePoint REST API med den anropandes delegerade token (user_impersonation).
  4. Metadata-rensning: SharePoint-kolumnen ColdStoragePath töms på filen för att markera att den inte längre är arkiverad.
  5. Blob-radering: Källbloben raderas från containern (kräver att ARCHIVE_DELETE_SOURCE=true eller sker alltid vid restore).
Konfliktshantering: Om en fil med samma namn redan finns i SharePoint-biblioteket läggs suffixet _restored till filnamnet automatiskt. Inga data skrivs över utan explicit bekräftelse.
Begränsning: Filer som arkiverades med ARCHIVE_DELETE_SOURCE=false finns fortfarande kvar i SharePoint. I så fall kopierar funktionen ändå tillbaka bloben och uppdaterar ColdStoragePath-kolumnen, men radering av dubblett är användarens ansvar.

Kapitel 4 — Arkiveringsfunktion

4.6 Massarkivering av omfång (ArchiveScope)

HTTP-funktionen ArchiveScope arkiverar allt inom ett valt omfång i ett enda anrop — en mapp (inklusive alla undermappar), ett helt dokumentbibliotek eller en hel webbplats (samtliga dokumentbibliotek). Rollen ColdStorage.Download krävs. Tillägget anropar funktionen från panelens knappar "Arkivera mapp / bibliotek / webbplats".

scopeTypeVad som gås igenom
folderAngiven mapp och alla undermappar rekursivt.
libraryBibliotekets rotmapp rekursivt.
siteVarje dokumentbibliotek på webbplatsen (BaseTemplate eq 101), rekursivt.

Mappvandringen sker via GetFolderByServerRelativeUrl(…)?$expand=Files,Folders. Systemmappar (Forms och mappar som börjar med _) hoppas över. Funktionen är idempotent: en fil vars blob redan finns hoppas över, liksom befintliga *.coldstorage.txt-platshållare. Svaret innehåller en sammanräkning: { ok, counts: { scanned, archived, skipped, failed } }. Timer-funktionen använder samma pipeline över det konfigurerade biblioteket.

4.7 Bevarande av unika behörigheter

Om en fil eller mapp har unika behörigheter (bruten behörighetsarv, HasUniqueRoleAssignments = true) fångas dessa innan arkivering och återställs vid restore — så att åtkomsten blir densamma efteråt.

  1. Fångst: rolltilldelningarna läses via roleassignments?$expand=Member,RoleDefinitionBindings och sparas som en följeslagar-blob {sökväg}.perms.json bredvid mediabloben. Den automatiska rollen "Begränsad åtkomst" (1073741825) filtreras bort.
  2. Återställning: vid restore bryts arvet på det återställda objektet (breakroleinheritance) och varje sparad tilldelning läggs tillbaka (addroleassignment(principalid, roledefid)).
Obs: om en fångad användare/grupp inte längre finns vid återställning hoppas den tilldelningen över — resten återställs ändå.

Kapitel 4 — Arkiveringsfunktion

4.8 Platshållare och enklicks-återställning

När en källfil tas bort vid arkivering lämnas en platshållare kvar på samma plats — en textfil med namnet <Originalnamn>.coldstorage.txt. Den fyller två syften: den talar om för en människa hur filen återställs utan tillägget om det någonsin slutar fungera, och den låter tillägget återställa filen med ett klick.

Innehåll i platshållaren

  • Läsbara instruktioner: var bloben finns (container och sökväg), vem som arkiverade och när, samt de manuella stegen för återställning.
  • Ett maskinläsbart block som tillägget tolkar, avgränsat exakt med ----SPCS-RESTORE-JSON---- och ----END----, med fälten coldStoragePath, sourceUrl, originalName, container, archivedDate, hadUniquePermissions.

Platshållarens listobjekt får kolumnen ColdStoragePath ifylld, så att tillägget känner igen den i biblioteksvyn.

4.9 Azure Function — återställning från platshållare

HTTP-funktionen RestoreFromPlaceholder tar antingen { placeholderServerRelativeUrl } (tillägget skickar platshållarens server-relativa URL) eller de redan tolkade fälten { coldStoragePath }. Rollen ColdStorage.Download krävs.

  1. Läser platshållartexten via kSPRestFilesCore.GetFileText och tolkar JSON-blocket.
  2. Kopierar bloben tillbaka till sourceUrl (med suffixet _restored vid namnkonflikt).
  3. Återställer eventuella unika behörigheter (§4.7).
  4. Tar bort platshållarfilen och sedan bloben (samt .perms.json).
Enklicks-återställning: i tillägget räcker det att markera en .coldstorage.txt-fil och klicka Återställ — hela flödet ovan sker automatiskt.

6.2 Begränsningar och skalning

SharePoint-begränsning (throttling)

SharePoint begränsar API-anrop per tidsenhet. Vid arkivering av stora bibliotek (>10 000 filer) bör följande strategier implementeras:

  • Delta-crawl: Lagra tidsstämpeln för senaste körningen i Function App Configuration och filtrera anrop med $filter=Modified gt '{timestamp}'. Reducerar API-anrop med >90 % på etablerade klientorganisationer.
  • Exponentiell backoff: Vid HTTP 429 vänta Retry-After-sekunder (finns i svarshuvudet) innan nästa anrop. Implementera med max 5 försök per fil.
  • Batchstorlek: Processar max 500 filer per körning. Konfigureras via ARCHIVE_BATCH_SIZE. Nästa batch körs vid nästa schemalagda tillfälle.

6.3 Kostnadsuppskattning

Använd följande formel för att beräkna månadsbesparing innan driftsättning:

Formel: månadsbesparing

Besparing = Volym_GB × (SP_kostnad − Cold_kostnad) × SEK/USD

Exempel: 100 GB arkiverat material
100 × (0,20 − 0,004) × 11,5 ≈ 225 kr/mån

Referenspriser (USD/GB/mån)

SharePoint Online: ~0,20
Azure Cold: ~0,004
Azure Archive: ~0,001
Priser varierar per region och avtal. Verifiera alltid i Azure Pricing Calculator.

Transaktionstillägg

Varje visning genererar en GET-transaktion (~0,004 USD/10 000 ops). Vid hög visningsfrekvens (>50 000/mån) kan transaktionskostnaden börja synas — övervaka i Azure Cost Management.

Azure Pricing Calculator

Detaljerade prisberäkningar per region, redundansnivå och transaktionsvolym görs i Microsofts officiella kalkylator: azure.microsoft.com/pricing/calculator

Tumregel: För en organisation med 500 GB gamla mediafiler i SharePoint är den typiska besparingen ~1 100 kr/mån (13 200 kr/år) — med bibehållen omedelbar åtkomst via SP Cold Storage.
