Episode brief

This episode sets everything up from zero — Claude Code, the Azure CLI, and a first sign-in to Azure — then teaches the read, change and delete mindset by doing each one on real resources.

Running time
About 10 minutes.
Surface
Azure CLI (az), run by Claude Code in the Visual Studio Code terminal.
Viewer can then
Read a subscription, make a safe change, and delete a resource — each with the right amount of review.
Prerequisites
None beyond a machine with Visual Studio Code and an Azure subscription. This episode installs Claude Code and the Azure CLI, and signs in.

Recording setup

  • A clean Visual Studio Code, so the extension install is shown on screen; the Claude Code panel and a docked terminal appear once it is added.
  • A test subscription with a few resource groups (one holding a web app), so the reading task has something to show.
  • Permission mode is set to bypass, so reads and safe changes run without a click. The delete guardrail comes from a CLAUDE.md rule, not from the permission prompt.

Companion text

The copy below is the companion page for the video, written in the Langate Tips voice. It is what a reader sees under the embedded demo.

Manage a whole Azure subscription with AI

A Manage Azure with Claude Code tutorial by Langate

It is possible to manage a whole Microsoft Azure subscription with AI, using Claude Code in Visual Studio Code — describing what you want in natural language rather than clicking through the Azure portal, and opening the portal to check the results.

In the demo below, Langate shows how to set up Claude Code, connect to an Azure subscription, and then manage its resources with Claude. The presenter reads the subscription, makes a safe change, and deletes a test resource — each with the right amount of review.

The demo keeps a simple rule in mind. Reading is safe, so Claude runs it freely. A change is approved after the presenter reads the command. A delete is always described first, and the presenter confirms it before it runs. A rule in the project CLAUDE.md file makes Claude follow that habit, even in bypass permission mode.

In the next episode the presenter explores the subscription by asking — resource groups, what is running, and what it costs.

Scene 4Changing — and letting Claude recover1:45 – 4:00

Say
"Now a change — something that actually alters the subscription. So here I read Claude's command before it runs. And this is the important part of the whole course: I set a goal, I let Claude try, and if it slips, I watch how it recovers."
Prompt
Create a resource group called rg-azure-demo in Sweden Central, then create a storage account named DemoStorage2026 inside it.
Claude
Proposes the group first. The presenter reads it — right name, right region, only creates.
az group create --name rg-azure-demo --location swedencentral --tags env=demo
Approved and run — provisioning state Succeeded.
Claude
Then proposes the storage account, keeping the name the presenter asked for.
az storage account create --name DemoStorage2026 --resource-group rg-azure-demo \ --location swedencentral --sku Standard_LRS
On screen
The command fails. Azure rejects the name: storage account names must be 3–24 characters, lower-case letters and numbers only.
Claude
Reads the error, explains the rule, and retries with a valid, lower-case name — noting it must also be globally unique.
az storage account create --name demostorage2026 --resource-group rg-azure-demo \ --location swedencentral --sku Standard_LRS
Succeeds.
Say
"That is the pattern I want you to get comfortable with. I set a goal, Claude made a reasonable attempt, Azure pushed back, and Claude read the error and corrected itself — lower-case name, and it remembered the name has to be unique. I did not have to know that rule in advance. I had to read what Claude proposed, and let it learn from the error."

Scene 5A guardrail in CLAUDE.md4:00 – 5:30

Say
"Before we delete anything, let us set up a safety net that lives in the project. Deleting is the one kind of task I never want to run by accident — even in bypass mode."
On screen
Open CLAUDE.md in the editor.
Prompt
Let's add a safety rule to CLAUDE.md: always check with me before you delete or replace anything, even in bypass mode. And note our defaults — Sweden Central, and rg-project-purpose naming.
Claude
Proposes an edit to CLAUDE.md. The presenter reads the added section on screen.
CLAUDE.md## Azure safety - Before running any command that deletes or replaces an Azure resource, describe in plain words exactly what will be removed and wait for my confirmation — even in bypass permission mode. - Default region: Sweden Central (swedencentral). - Resource-group naming: rg-<project>-<purpose>.
Say
"Now that rule is part of the project's memory. Claude reads CLAUDE.md at the start of every session, so from now on it will stop and describe any delete before running it. CLAUDE.md is the project's memory file — and now it is holding a guardrail."

Scene 7Where CLAUDE.md lives — and sharing it across projects7:00 – 8:00

Say
"That guardrail lives in this project's CLAUDE.md. But you will manage more than one Azure project, and you do not want to write the same safety rules into every one. So let me show you where this file lives — and how to keep the rules in one place."
Prompt
Where does Claude Code look for CLAUDE.md files, and how can I keep my Azure safety rules in one central file that all my projects share?
Claude
Explains that it reads two kinds of memory file. It looks for project memory — a CLAUDE.md in the project folder, which travels with the project and is shared with anyone who has the code — and personal memory at ~/.claude/CLAUDE.md in your home folder, which it reads for every project on your machine.
Say
"So there are two homes already: one that ships with the project, and one personal file that applies everywhere. For shared rules like our safety net, I want a third option — one central file that I write once and point every project at."
Claude
Proposes one central file holding the shared rules, then a single @ line in each project's CLAUDE.md that pulls it in. The referenced path can be relative, absolute, or start at your home folder with ~.
~/azure-standards/CLAUDE.md — the central file, written once## Azure safety - Before deleting or replacing a resource, describe exactly what will be removed and wait for confirmation — even in bypass mode. - Default region: Sweden Central (swedencentral). - Resource-group naming: rg-<project>-<purpose>.
the project's CLAUDE.md — one line pulls the central file in@~/azure-standards/CLAUDE.md ## This project - Test subscription; safe to create and delete demo groups.
Say
"Now the safety rules live in one place. Every project just references that central file, so Claude reads the same rules everywhere. Change the central file once and every project follows — no copy-and-paste, and nothing to keep in sync by hand."

Scene 8Save the working pattern as a skill8:00 – 9:30

Say
"We have found a way of working that works: set a goal, read the command before it runs, let Claude recover from errors, and clean up afterwards. When a pattern proves itself like that, we save it as a skill — so Claude does it the same way next time, without me repeating the rules."
Prompt
Save the way we just worked as a skill — call it managing-azure-safely — so you'll do it the same way next time, without me repeating the rules.
Claude
Proposes a new skill file. The presenter reads it on screen.
skills / managing-azure-safely / SKILL.md--- name: managing-azure-safely description: Manage Azure with AI - set a goal, propose the az command, wait for review, recover from errors, confirm deletes. --- # Managing Azure safely 1. Take the goal in plain words; restate it before acting. 2. Propose one `az` command and wait — do not run changes unread. 3. If Azure returns an error, read it, explain the cause, and retry. 4. Before any delete or replace, describe exactly what will be removed and wait for confirmation. 5. Default region swedencentral; groups named rg-<project>-<purpose>. 6. Clean up test resources when the task is done.
Say
"Now that lesson is not just in my head, or in one line of CLAUDE.md — it is a reusable skill. In the coming episodes we keep doing exactly this: set a goal, let Claude try and sometimes fail, learn from the error, and save what works as a skill. That is how the course builds a toolbox that keeps getting better."
