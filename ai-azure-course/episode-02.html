Episode brief

The first hands-on episode after the getting-started episode. It is all reading — the safest kind of task — so every command just runs. The audience learns to get a whole picture of a subscription by asking three questions, and sees the learning loop again when Claude's first cost command turns out to be the wrong one.

Running time
About 9 minutes.
Surface
Azure CLI (az), read-only, run by Claude Code in the Visual Studio Code terminal.
Viewer can then
Ask what is in a subscription, what is running, and what it costs — and recognise a wrong command from a right one.
Prerequisites
Episode 1. The managing-azure-safely skill saved there is already in the project, so Claude follows the read / change / delete rules from the start.

Claude reads the project's CLAUDE.md at the start of every session, so the delete guardrail written in Episode 1 is still in force here. As you add more Azure projects, keep such rules in one central CLAUDE.md and reference it from each — every project then inherits the same safety net.

Recording setup

  • A test subscription with a few resource groups, one or two virtual machines (at least one running, one stopped), a web app, and a little cost history.
  • Visual Studio Code with the Claude Code panel and the terminal docked below.
  • Permission mode is bypass; because everything here is reading, nothing needs approval.

Companion text

The copy below is the companion page for the video — what a reader sees under the embedded demo.

Explore an Azure subscription by asking

A Manage Azure with Claude Code tutorial by Langate

It is possible to get a full picture of a Microsoft Azure subscription just by asking Claude Code in plain words, rather than clicking through the Azure portal — though the portal is still the place to see a result in full.

In the demo below, Langate shows how to answer three questions by chatting: what is in the subscription, what is running right now, and what it has cost this month. Reading never changes anything, so every command runs without approval.

The cost question does not go smoothly at first. Claude's first command is one that sounds right but is no longer part of the tooling, so it fails. Claude reads the error and switches to the command that works. The presenter keeps that habit from the last episode: set a goal, let Claude try, and let it learn from the error.

In the next episode the presenter moves from reading to changing — creating, starting, resizing and deleting virtual machines to save money.

Scene 4What is it costing — the loop again4:15 – 6:30

Say
"The third question is cost. And this is where the learning loop shows up again. I set the goal, I let Claude try, and I watch what happens when its first idea does not work."
Prompt
What has this subscription cost so far this month, and which resource group is the most expensive?
Claude
Tries a cost command that is widely quoted online.
az costmanagement query --type ActualCost --timeframe MonthToDate \ --scope /subscriptions/<id>
On screen
It fails. The costmanagement extension no longer has a query command — only export and show-operation-result — so az reports that query is not recognised.
Claude
Reads the error, explains that the command it reached for has been removed, and switches to the core consumption command — noting it is in preview.
az consumption usage list --start-date 2026-07-01 --end-date 2026-07-11 \ --output table
Then it groups the result and answers: total so far, and the most expensive resource group.
Say
"There is the loop. Claude's first command sounded right — I have seen it in old blog posts myself — but it is not in the tooling any more. Claude read the error, told me what had changed, and found the command that works. I did not have to know which one was current."

Scene 5Save the exploration as a skill6:30 – 8:00

Say
"These three questions are ones I ask in every subscription. So let us do what we did last time — save what works as a skill, so I can get the whole picture by asking once."
Prompt
Save this exploration as a skill called exploring-a-subscription, so I can get the whole picture by asking once — and remember to use the cost command that actually worked.
Claude
Proposes a new skill file. The presenter reads it on screen.
skills / exploring-a-subscription / SKILL.md--- name: exploring-a-subscription description: Read-only overview of an Azure subscription - resource groups, what is running, and month-to-date cost. --- # Exploring a subscription Reading only - never change or delete. 1. Groups: `az group list` + `az resource list`, summarised one line per group (region, resource count). 2. Running: `az vm list --show-details` (power state) and `az webapp list`. 3. Cost: `az consumption usage list` (preview) for the current month; group the total by resource group.
Say
"Now the whole overview is one skill. A new session, or a colleague, can get the same picture by asking once — and it already knows to use the cost command that works. Another skill in the toolbox, and it started from a mistake."
